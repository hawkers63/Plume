### Finding 2: Gender Agreement Requires Explicit French Context
**Severity:** Medium product requirement.

French gender agreement diverges from English gender norms, impacting French adjectives and certain past participles, particularly in first-person and second-person constructions:

- "I am happy" translates to "Je suis contente" for a woman, and "Je suis content" for a man.
- "I went" translates to "Je suis allée" for a woman, and "Je suis allé" for a man.
- "Are you ready?" translates to "Tu es prête ?" for a woman, and "Tu es prêt ?" for a man.

A single "French gender" setting would be ambiguous, as conversations typically involve two individuals:

- The user/speaker, represented as "I", "me", or "we".
- The other participant/addressee, represented as "you".

The primary use case involves woman-to-woman dialogue, thus Plume should accommodate feminine agreement for both participants while still permitting masculine or neutral settings when required.

**Recommended Product Model:**
Introduce two French agreement controls:

1. "Me" or "Speaker": Feminine / Masculine / Avoid where possible
2. "You" or "Other person": Feminine / Masculine / Avoid where possible

**Recommended UI:**
Position these controls in the top toolbar, as they influence the subsequent translation and may require adjustments during live conversation. A practical layout would be:

**Direction | French Form | Me: Feminine | You: Feminine | Settings**

Utilise compact `CTkOptionMenu` controls rather than a settings-only preference. The settings can still retain the defaults, but the live toolbar should make them accessible.

**Suggested Constants:**
```python
GENDER_FEMININE = "Feminine"
GENDER_MASCULINE = "Masculine"
GENDER_AVOID = "Avoid where possible"
FRENCH_GENDERS = (GENDER_FEMININE, GENDER_MASCULINE, GENDER_AVOID)
```

**Suggested Config Keys:**
```python
"default_french_speaker_gender": GENDER_FEMININE,
"default_french_recipient_gender": GENDER_FEMININE,
```

If maintaining a general-public default is preferred, utilise `GENDER_AVOID` for both options and allow users to specify woman-to-woman defaults in Settings. For the primary user group, Feminine/Feminine is the most effective working default.

**Prompt Change:**
Revise the current generic gender-avoidance clause in `build_translation_prompt()` to incorporate a clause that respects the selected French agreement context.

**Suggested Code Direction:**
```python
def build_gender_clause(speaker_gender, recipient_gender):
    return (
        "French gender agreement context: use {speaker} agreement for the "
        "speaker/user in first-person French wording, and {recipient} "
        "agreement for the addressee/other person in second-person French "
        "wording. When the source text explicitly marks gender, preserve "
        "that explicit meaning. When the selected value is 'Avoid where "
        "possible', prefer natural wording that does not require gendered "
        "agreement; if gendered wording cannot be avoided, use a concise "
        "note rather than guessing."
    ).format(speaker=speaker_gender.lower(), recipient=recipient_gender.lower())
```

Then invoke this function from `build_translation_prompt()` and include the same values in `build_user_envelope()`:
```python
"French speaker agreement: {}\n"
"French addressee agreement: {}\n"
```

**Behavioural Rules for the Model:**
- For translations from English to French, apply the gender settings to the generated French output.
- For translations from French to English, refrain from inferring gender in English. Use the settings solely to interpret ambiguous or inclusive French wording where relevant.
- If the French source explicitly states "content" or "contente", prioritise the source over the toolbar setting.
- If the sentence encompasses both "I" and "you", apply both settings.
- If the sentence is gender-neutral in French, do not enforce gendered wording.

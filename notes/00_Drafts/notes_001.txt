plume.py is a single, well-sectioned CustomTkinter application. The

------------------------------------------------------------------------
1. Executive Summary
------------------------------------------------------------------------
Overall the codebase is mature, well-organised and consistent with the
project specification: it has an import-safe deterministic core, a
strict JSON response contract, atomic config writes, placeholder
protection with privacy-preserving warnings, masked API-key display
and a stale-callback guard for the worker thread. The documentation
matches the implementation in almost every place I checked.

The issues that exist are concentrated in three areas:
  (a) state-handling around the in-flight translation lifecycle
      (Clear, window close, status-bar text, privacy-notice persistence);
  (b) hygiene of the project tree (a duplicate test file, no .gitignore
      despite a live API key sitting in plume_config.json, one piece of
      dead state);
  (c) two small UX gaps the user is likely to feel (the status bar
      never shows "translating…", and the language-direction toolbar
      change can be silently clobbered by an unrelated Settings save).

None of the bugs lead to data loss or to leaking the submitted phrase
into diagnostics; the privacy guarantees described in the README hold.
The deterministic parser, prompt builder, placeholder pipeline and
config atomicity are all correct and well covered by tests.

Three new features are proposed at the end of this report. Each is
small, modular, fits the lightweight conversational-helper remit and
ships with a placement note and a fully documented snippet.

2. Identified Bugs and Severity
------------------------------------------------------------------------

BUG 1 — Live API key committed alongside a missing .gitignore
  Severity : CRITICAL (security)
  Location : C:\Plume\plume_config.json
             C:\Plume\ (no .gitignore file)
  The live plume_config.json contains a real Anthropic key:
      "anthropic_api_key": "sk-ant-api03-...dhiLSQAA"
  The README instructs "Do not commit your live file", but the
  project ships without a .gitignore, so a single `git add --all`
  (which the project's own commit protocol uses) would publish the
  key. The example config is correct, the live file is not ignored.
  Recommended fix: ship a .gitignore that excludes plume_config.json
  and the build / pycache artefacts. Snippet in §3.1.

BUG 2 — Stale callback guard is bypassed by Clear
  Severity : MODERATE (logic / state-handling)
  Location : plume.py, PlumeApp._clear  (around line 1218)
  The project specification states: "Ignore a result if a later
  request, Clear action, or window close has superseded it." The
  implementation increments self._request_id only inside _translate
  (line 1284). _clear mutates UI state and empties the input but
  never bumps the request id, so an in-flight worker thread whose
  result arrives after Clear is NOT marked stale by
  result_is_stale(rid, self._request_id). The result is then
  rendered, with the "Generated for an earlier message" advisory
  appended. The user sees the cleared input re-populated by a stale
  translation, which is the opposite of the documented behaviour.
  Recommended fix: have _clear increment self._request_id so any
  in-flight result is dropped. Snippet in §3.2.

BUG 3 — format_status silently discards the `state` argument
  Severity : MODERATE (UX / state-handling)
  Location : plume.py, format_status  (lines 817-829)
             plume.py, _refresh_status  (lines 1205-1208)
  Inside format_status, the right-hand field is computed as:
      right = state if state else "ready"
      if char_count is not None:
          right = "{} characters".format(char_count)
  Because _refresh_status is always called with the live char count
  (line 1207), the `if char_count is not None` branch is always
  taken, and the `state` value is overwritten. The user therefore
  never sees "translating…" or "ready" in the status bar — the bar
  always reads "Backend: … | N characters", even while a request is
  in flight. The Translate button still changes its label, so the
  feature is half-broken rather than fully absent.
  Recommended fix: only fall back to the character count when the
  caller did not request an explicit non-default state. Snippet in
  §3.3.

BUG 4 — Window close during translation can raise TclError
  Severity : MODERATE (state-handling / robustness)
  Location : plume.py, PlumeApp._translate, worker closure
             (around line 1301)
  The worker schedules its result with:
      self.after(0, lambda: self._deliver(rid, text, payload))
  If the user closes the main window while a worker is in flight, the
  scheduled callback still runs against a destroyed widget tree and
  raises a TclError ("invalid command name …"). The project
  specification explicitly says "Close during a request produces no
  Tk callback exception." The only protection today is the broad
  `except Exception` in the worker body, which does not cover the
  `self.after(0, ...)` call itself or the _deliver body.
  Recommended fix: guard the after() call and the deliver body
  against a destroyed root. Snippet in §3.4.

BUG 5 — Privacy notice silently swallows save failures
  Severity : MINOR (data consistency / UX)
  Location : plume.py, PlumeApp._translate  (lines 1279-1282)
  When the user accepts the privacy notice, the code persists
  privacy_ack with:
      try:
          save_config(self.config_data)
      except ConfigError:
          pass
  If the existing config file is damaged and an automatic save fails,
  the acknowledgement is dropped on the floor with no message. The
  next launch re-shows the notice, and the user has no idea why.
  Recommended fix: surface a small advisory when the persist fails
  but do not abort the in-flight translation. Snippet in §3.5.

BUG 6 — Duplicate test file outside tests/
  Severity : MINOR (project hygiene)
  Location : C:\Plume\test_translator_logic.py
             C:\Plume\tests\test_translator_logic.py
  Both files are byte-identical (SHA256

  The unittest discovery command in the README points at `tests`,
  so the top-level copy is never run, but it will drift the moment

  copy and rely on the canonical tests/ location. The two

BUG 7 — Dead state on PlumeApp
  Severity : MINOR (cleanup)
  Location : plume.py, lines 1036 and 1286
  self._active_snapshot is initialised in __init__ and assigned in
  _translate but never read. It is a vestige of an earlier design
  and adds nothing today. Recommended fix: remove both assignments.

BUG 8 — Direction toolbar change is in-memory only and can be
        silently lost on next launch
  Severity : MINOR (data consistency / UX)
  Location : plume.py, _on_direction_change  (line 1198)
  Changing the Direction segmented button writes to
  self.config_data in memory but never calls save_config. The
  project spec calls toolbar choices "session-only", so this is
  intentional; however, opening Settings, clicking Save, and
  closing Settings now persists every other field but not the
  toolbar's direction selection, because the SettingsDialog
  does not include a direction field. The user's deliberate
  direction change is overwritten on next launch by the
  config-file default. Recommended fix: when Settings saves,
  apply the current toolbar direction into the saved config
  (one line). Snippet in §3.6.

BUG 9 — privacy_ack is duplicated between config_data and snapshot
        in a way that can cause privacy notice to re-appear
  Severity : MINOR (state-handling)
  Location : plume.py, _translate  (lines 1277-1278)
  After the user accepts the notice, both config_data and
  snapshot are updated. The save_config call is in a try/except
  that silently swallows errors. The snapshot's privacy_ack is
  correct, so the in-flight translation proceeds, but if save
  fails, the next session still needs the notice. This is the
  same root cause as Bug 5; fixing Bug 5 also resolves this.

4. Three Proposed New Features

All three are designed to be added without changing the JSON

------------------------------------------------------------------
4.1  Session-only recent-translation strip
------------------------------------------------------------------
Rationale
  The project spec calls local history "off by default and not
  stored in version 1", but a small in-memory strip of the last
  few translations is useful when the user is iterating on a
  phrasing and wants to re-copy a previous attempt without
  re-typing. Memory-only, no file write, no consent needed.
  Sits naturally below the alternatives scrollable frame.

Behaviour
  - Maintains a deque of the last N results (default 5).
  - Each row shows "source → target · confidence" plus a single
    Copy button that copies the main translation.
  - Cleared when the user explicitly clears, when the backend
    changes, or when the window closes.
  - A small "Show recent" toggle reveals / hides the panel.

Snippet (modular addition to PlumeApp)

    # --- Session-only history strip ----------------------------------
    # Append immediately AFTER the `_variation_cards = []` line in
    # PlumeApp.__init__ (around line 1037).

    from collections import deque
    HISTORY_LIMIT = 5

    def _build_history(self):
        """Create the collapsible recent-translations strip.

        Hidden by default. Each entry is a frame with the
        source-target label and a Copy button. Memory only; never
        written to disk.
        """
        self._history = deque(maxlen=HISTORY_LIMIT)
        self._history_rows = []
        self._history_visible = False

        self.history_toggle = ctk.CTkButton(
            self.alts_frame.master,
            text="Show recent",
            width=140,
            command=self._toggle_history,
            fg_color="gray30",
        )
        # Positioned under the advisory strip.
        self.history_toggle.grid(
            row=5, column=0, sticky="w", padx=12, pady=(0, 10)
        )
        self.history_toggle.grid_remove()

        self.history_frame = ctk.CTkFrame(self.alts_frame.master)
        self.history_frame.grid(
            row=6, column=0, sticky="ew", padx=12, pady=(0, 10)
        )
        self.history_frame.grid_columnconfigure(0, weight=1)
        self.history_frame.grid_remove()

    def _toggle_history(self):
        self._history_visible = not self._history_visible
        if self._history_visible:
            self.history_frame.grid()
            self.history_toggle.configure(text="Hide recent")
        else:
            self.history_frame.grid_remove()
            self.history_toggle.configure(text="Show recent")

    def _push_history(self, text, result):
        """Add a translation to the in-memory history strip."""
        if not isinstance(result, dict):
            return
        entry = {
            "source_language": result.get("source_language", ""),
            "target_language": result.get("target_language", ""),
            "main_translation": result.get("main_translation", ""),
        }
        if not entry["main_translation"]:
            return
        self._history.appendleft(entry)
        self._redraw_history()

    def _redraw_history(self):
        for row in self._history_rows:
            row.destroy()
        self._history_rows = []
        for index, entry in enumerate(self._history, start=1):
            label = "{} \u2192 {} \u00b7 {}".format(
                entry["source_language"],
                entry["target_language"],
                entry["main_translation"],
            )
            row = ctk.CTkFrame(self.history_frame)
            row.grid(row=index, column=0, sticky="ew", pady=2, padx=2)
            row.grid_columnconfigure(0, weight=1)
            ctk.CTkLabel(row, text=label, anchor="w", wraplength=420,
                         justify="left").grid(row=0, column=0, sticky="ew", padx=8, pady=4)
            ctk.CTkButton(row, text="Copy", width=70,
                          command=lambda t=entry["main_translation"]: self._copy(t)
                          ).grid(row=0, column=1, padx=8, pady=4)
            self._history_rows.append(row)
        if self._history:
            self.history_toggle.grid()

Wiring
  - Call self._build_history() at the end of _build_right

  - Call self._push_history(text, data) at the end of _deliver,

    def _safe_register(value):

4.3  "Translate back" verification button
------------------------------------------------------------------
Rationale
  Conversational helpers are often used to sanity-check a phrase
  the user is about to send. A small "Translate back" button
  next to the main translation card re-runs the pipeline on the
  main translation, in the opposite direction, and displays the
  round-trip result as a third advisory line. The user can then
  judge whether the meaning survived.

Behaviour
  - Disabled until a result is on screen.
  - Reverses source and target, runs the standard worker
    pipeline, and shows a single-line "Round-trip: …" advisory.
  - Snapshots the current config the same way Translate does, so
    the round-trip uses the same backend and formality.

Snippet

    # Add as new methods on PlumeApp, just after _render_result.

    def _build_reverse_button(self):
        """Add the 'Translate back' button to the primary card."""
        self.reverse_btn = ctk.CTkButton(
            self.primary_card,
            text="Translate back",
            command=self._reverse_translate,
            fg_color="gray30",
        )
        # Sits between the copy button (row 1) and the next row.
        self.reverse_btn.grid(
            row=2, column=0, sticky="ew", padx=12, pady=(0, 12)
        )
        self.reverse_btn.configure(state="disabled")

    def _reverse_translate(self):
        """Translate the current main translation back into its
        source language as a sanity check."""
        if not self._current_main:
            return
        # Force the opposite direction.
        current = self.direction_var.get()
        if current == DIR_EN_FR:
            self.direction_var.set(DIR_FR_EN)
        elif current == DIR_FR_EN:
            self.direction_var.set(DIR_EN_FR)
        # DIR_AUTO: keep the current direction; the user can flip
        # it manually before clicking if needed.
        self._translate()

    def _show_round_trip(self, original_source, roundtrip_text):
        """Show a compact round-trip note without overwriting the
        visible result."""
        self.advisory_round_trip = getattr(self, "advisory_round_trip", None)
        if self.advisory_round_trip is None:
            self.advisory_round_trip = ctk.CTkLabel(
                self.primary_card, text="", text_color="gray65",
                justify="left", anchor="w", wraplength=460,
            )
            self.advisory_round_trip.grid(
                row=3, column=0, sticky="ew", padx=12, pady=(0, 12)
            )
        self.advisory_round_trip.configure(
            text="Round-trip (back into {}): {}".format(
                original_source, roundtrip_text
            )
        )

#### 1. EXECUTIVE SUMMARY  

A. It is proposed to add an About panel directly beneath the Settings heading. This panel will display the application name, current version, purpose, and the existing copyright notice:  
*Copyright (c) 2026 Mark Hawksworth. All rights reserved.*  

This addition will enhance ownership visibility within the application and eliminate the need for an additional toolbar control or window.

B. A "Lowercase translations" checkbox is recommended to be added beneath the output alternatives. This feature will convert the displayed and copied translation text to lowercase locally, including any finishing touches. Unchecking the box will restore the original casing immediately. For example, "Je viens d'Auridia ! xD" will be transformed to "je viens d'auridia ! xd". There will be no additional costs associated with translation requests or API usage.

It is advisable to conduct two separately reviewable releases: the About panel first, followed by the lowercase feature. Version numbers will remain unassigned until implementation is authorised.

The five priority areas outlined in the standing mandate will be evaluated against the current code. These areas serve as context and do not represent five additional unimplemented features. The two additions specified above are the focus of this note.

#### 2. DETAILED ARCHITECTURAL PROPOSALS  

**2.A About panel**  

A compact CTkFrame should be placed within the existing scrollable body of the SettingsDialog, directly after the Settings heading and before the Backend selector. It will display the text "About Plume — v1.53", with the version indicated by APP_VERSION, followed by "French ↔ English conversation helper" and the copyright notice.

Utilise the owner and year as specified in C:\Plume\COPYRIGHT and C:\Plume\LICENSE. This proposal aims to present their existing attribution without modifying the licence. The copyright year should not be calculated based on the current date, nor should an email address or ownership claim be fabricated.

The short notice should be stored as a module-level APP_COPYRIGHT constant adjacent to APP_NAME/APP_VERSION. This serves as release metadata rather than user configuration, thus avoiding issues with a missing external COPYRIGHT file in a frozen executable. The constant should be reviewed against COPYRIGHT and LICENSE whenever attribution changes occur. No new bundled resources, dependencies, JSON fields, threads, or network calls will be introduced.

**Visual specification:** The existing Settings dimensions are 560x780, with a minimum size of 480x480; outer horizontal padding should be 16, and vertical padding 8; panel inner padding should be 12; corner radius should be 8; the dark panel colour is #242424; main text colour is #F2F2F2; secondary text colour is #C7C7C7; use Segoe UI 15 for bold headings and 13 for body text. The two body labels should wrap to fit the available panel width. The existing fixed Save/Cancel footer will remain outside the scrolling body; there is no need for an additional dialogue.

**2.B Lowercase translations: behavioural contract**  

The Unicode str.lower() function should be applied solely at the presentation/clipboard boundary. The variables _current_main and _current_result should retain their original forms. Input, prompt, response JSON, glossary, or history storage must not be converted to lowercase. The use of casefold() is discouraged, as it is intended for caseless matching and may alter text more aggressively, such as converting German ß to ss. Python's lower() retains accents, but Unicode casing may change code-point counts, necessitating recalculation of metrics from the displayed string. References:  
- [Python str.lower() Documentation](https://docs.python.org/3/library/stdtypes.html#str.lower)  
- [Python str.casefold() Documentation](https://docs.python.org/3/library/stdtypes.html#str.casefold)  

**Scope matrix:**  
- **Surface**: Proposed behaviour when checked  
  - Main translation display: Lowercase, including appended touches  
  - Alternative translation labels: Lowercase; meaning checks remain unchanged  
  - Copy main / Reply: Lowercase composed translation  
  - Individual alternative Copy: Lowercase composed translation  
  - Copy five / Copy five as HTML: Lowercase translations; existing numbering  
  - Copy main as HTML: Same translation as plain Copy main  
  - Copy all: Lowercase main and alternative translations; source, situation, headings, and meanings retain their existing casing  
  - Copy source / phrasebook Copy: Existing original text  
  - History Copy / History export: Existing stored original text  
  - Markdown study sheet / diff export: Existing original-cased study material  
  - Speak / Use as input / Add glossary: Existing original translation  

This feature is intended as a chat-output preference, rather than a document-wide case converter. The "Use as input" function will maintain its existing raw-text semantics; pasting copied lowercase text will remain an option when this is deliberately desired. The clipboard for Reply will respect lowercase settings, while the context of previous exchanges will retain the original accepted translation. The Favourite and Undo Clear functions will preserve their raw snapshots; reopening either result will apply the current display mode.

Strict lowercase will also affect proper names, acronyms, Latin-letter emotes, Keep-as-is terms, and case-sensitive strings within the translated output. For instance, Auridia will become auridia, and xD will become xd. The Keep-as-is feature will still protect wording from translation, but this explicit local formatting mode will override casing in display and copy actions. The following help text should be displayed in the output footer:  
*"Display and chat copies only. Names and exact tokens also become lowercase."*  
This information is essential for the proposed feature, particularly regarding URLs, placeholders, and commands. Users who require precise casing should leave the option unchecked. Exceptions should not be introduced silently when this mode is activated.

**Ordering:** Raw translation → existing finishing-touch composition (where applicable) → lowercase → existing optional French typography for clipboard operations → HTML escaping/CF_HTML construction. Completed HTML markup should never be converted to lowercase. The Copy five function will continue to exclude touches, while Copy all will persist in adding touches to the main translation only. French typography will remain copy-only.

**State and persistence:** The initial release will use one ctk.BooleanVar, initially set to False, for the current application session. The Clear, Undo Clear, Reply, and new results will retain the selection; restarting Plume will reset it. There will be no changes to DEFAULT_CONFIG, plume_config.json, the example configuration, or history schemas. This is a deliberate scope choice; cross-session persistence has not been requested.

Should a remembered preference be required in the future, it is recommended to add lowercase_output: false to DEFAULT_CONFIG and the example configuration; only a JSON boolean should be accepted at load time (the string "false" must not activate it). The existing atomic save_config path should be employed, preserving protection against damaged files and reconciling SettingsDialog's open-time snapshot with the live output preference before saving. This extension will require its own save/failure tests and is not included in these session-only snippets.

**Visual specification:** Pin an output footer at right-pane grid row 6 beneath the row-5 alternatives; move the existing advisory to row 7. Row 5 should remain the sole vertically expanding output row. Use horizontal padding of 12 and bottom padding of 8; checkbox height should be 24, box dimensions 20x20, and width 220, with Segoe UI 13. The fill colour will be #1F6AA5, hover colour #144870, and text colour #F2F2F2. The help text should be placed on a separate wrapping line, using Segoe UI 12 and #C7C7C7. Budget approximately 60-80 logical pixels, depending on wrapping. It should not be assumed that the current alternatives viewport has spare height at 1000x600; this should be verified with a visible advisory and long results.

**Performance/lifecycle:** Six bounded strings will be reformatted upon toggling. Existing labels should be updated rather than rebuilding the result or cards. Calling _render_result on a toggle would reset a promoted "Use this" main translation, halt speech, and alter favourite states. No widget work should be conducted on a worker thread in this case; the callback will only perform in-memory formatting on the UI thread. An ongoing translation will continue normally and render with the current checkbox value when its accepted result arrives.

def format_translation_case(text: str, lowercase: bool = False) -> str:

    return text.lower() if lowercase else text

#### 3.E `PlumeApp` Methods — Insert Beside `_refresh_primary_display`

```python
def _display_translation(self, text):
    """Apply the live output preference to a raw translation."""
    return format_translation_case(text, self.lowercase_var.get())


def _on_lowercase_change(self):
    """Refresh text without resetting the accepted result or selection."""
    self._refresh_primary_display()
    variations = (self._current_result or {}).get("variations", [])
    for index, (card, variation) in enumerate(
        zip(self._variation_cards, variations), start=1
    ):
        card._translation_label.configure(
            text="{}. {}".format(
                index, self._display_translation(variation["translation"])
            )
        )
```

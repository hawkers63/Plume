------------------------------------------------------------------------
1. Feature
------------------------------------------------------------------------
Name: "Use this" -- promote an alternative to the working main translation

Rationale, grounded in the current code:

  Plume's dual pane exists so the user can compare the primary translation
  with five numbered alternatives. Today that comparison is display-only.
  Each alternative card in PlumeApp._render_result (plume.py, from
  approximately line 1581) offers a Copy button, but the primary card,
  self._current_main, and "Copy main translation" stay locked to
  result["main_translation"]. If the user prefers alternative 3, they
  must copy it as a one-off; the working translation never changes.

  That is the missing selection step. The dual pane should let the user
  adopt a preferred variation without a second API call and without
  leaving the comparison view.

  This is not on the existing roadmap (history, situation box, TTS,
  direction swap) and is not in notes_001 to notes_004 (history strip,
  tone labels, translate-back, alternatives layout, gender agreement,
  finishing-touch picker). Gender agreement and the alternatives heading
  removal have already landed in the live plume.py.

------------------------------------------------------------------------
2. User-visible behaviour
------------------------------------------------------------------------
After a successful translation:

  1. Each alternative card gains a compact "Use this" button above Copy.
  2. Clicking "Use this" replaces the primary card text with that
     alternative, points "Copy main translation" at it, and leaves the
     five cards in place so the user can still compare or change their
     mind.
  3. No network request is made. The model result is not re-parsed.
  4. Clear still wipes the primary text and disables copy-main, as now.
  5. A later Translate replaces the adopted text with the new result,
     as now.

The left-hand source pane is untouched. Formality, Me/You gender, and
direction are untouched.

Surrounding context: this sits with format_status / format_language_label

    def adopt_main_translation(current_main, candidate):
        """Return the adopted working translation.

        The candidate is favoured when it is a non-empty string after
        stripping. Otherwise the current main text is kept. This helper
        is import-safe so the behaviour can be tested without Tk.
        """
        text = (candidate or "").strip()
        if text:
            return text
        return current_main or ""


4.2 PlumeApp._use_as_main -- class PlumeApp

Insert immediately AFTER _copy(), currently around line 1436:

        def _copy(self, text):
            ...

Surrounding context: _copy is followed by _open_settings. Place the new
method between them.

        def _use_as_main(self, text):
            """Promote an alternative to the working main translation.

            The model is not contacted again. Only the displayed primary
            text and the copy-main target are updated, so the user can
            adopt a preferred variation without leaving the dual pane.
            """
            adopted = adopt_main_translation(self._current_main, text)
            if not adopted or adopted == self._current_main:
                if adopted:
                    self._set_primary_text(adopted)
                return
            self._current_main = adopted
            self._set_primary_text(adopted)
            self.copy_main_btn.configure(state="normal")

6. Risks
------------------------------------------------------------------------
  - Card height. Two stacked 80px buttons add a little vertical space.
    Acceptable at the current 4px card padding; if five cards overflow
    more than they do today, drop pady on the button column from 8 to 4.
  - Status bar. format_status currently overwrites an explicit state
    with the character count (open defect in notes_001 / notes_002).
    This feature therefore does not depend on the status bar.
  - Finishing-touch picker (notes_004), if later implemented, should
    read self._current_main so an adopted alternative is the text that
    receives the emoticon. No extra work is required if that picker is
    written against _current_main rather than the raw model field.

------------------------------------------------------------------------
7. Deliberately not proposed
------------------------------------------------------------------------
  - History / favourites, situation box, TTS, direction-swap button
    (already on the roadmap).
  - Translate-back / round-trip (notes_001). That checks YOUR text;
    "Use this" chooses among the current alternatives.
  - Finishing-touch emotes (notes_004). Complementary, not competing.
  - Highlighting the chosen card, Ctrl+1..5 shortcuts, or rewriting
    the JSON contract to mark a selected variation. Those can wait.

------------------------------------------------------------------------
1. Executive summary
------------------------------------------------------------------------
Plume is now a dense, single-purpose translator. The next useful work
is not another prompt control: it is making the existing machine faster
to feed, easier to find things in, and safer to interrupt — without
touching the JSON contract or adding HTTP libraries.

Recommended order (v1.32–v1.36):

  A. Crash-safe file intake — argv, Explorer Send to, paste-as-path.
     Reuses v1.28's reader. No WndProc.  (brief item 1, without the crash)
  B. User-defined Situation catalogue in plume_config.json.
     Completes brief item 2 without a second preset system.  (v1.33)
  C. Sticky register defaults (last tones + writing profile on launch).
     Three-tone combinator stays as-is.  (brief item 3, residual UX)
  D. Result-pane metrics, copy-all-five, optional French typography
     at copy time.  (brief item 4, the remaining slice)
  E. Cooperative cancel of an in-flight urllib call, plus an opt-in
     local Ollama fallback after Claude retries are exhausted.
     Not streaming.  (brief item 5, the remaining slice)

Small companion, same sitting if the layout still has room:

  F. History search box, and a tray "Show and paste clipboard" item
     that never auto-translates.

UX rationale: a conversation helper lives next to Explorer, the
clipboard and the tray. v1.18 proved we cannot intercept Explorer
drops in this Tcl/Tk build. We can still accept the same files through
every other Windows 11 path that does not subclass a WndProc. Situation
is the one catalogue still hard-coded while conversation presets are
user-defined — that inconsistency is what users will notice. Sticky
tones stop the "set Warm/Precise every session" tax. Copy-time
typography and copy-all-five make the result pane as useful as the
input pane already is. Cancel and a local fallback stop the "Clear did
nothing, Claude is still billing" feeling.

No new third-party HTTP packages. The only new Windows surface is a
SendTo .cmd (standard library + one file write). CustomTkinter stays
the GUI. File intake never submits text to either backend.

2. Detailed architectural proposals
------------------------------------------------------------------------

2.A  Crash-safe file intake  (v1.32)
------------------------------------
v1.28 already reads .txt/.md on a worker via read_import_text()
(line 1283) and _begin_file_import() (line 4003). The missing piece is
getting a path *into* that function without dragging onto the window.

Three intakes, one worker:

  1. Command line. Frozen: `Plume.exe --import "D:\draft.txt"`.
     From source: `python plume.py --import "D:\draft.txt"`.
     Extra positional paths are ignored after the first, with one
     advisory. `--start-minimised` remains valid and orthogonal.
  2. Explorer Send to. Settings checkbox, off by default, writes
     `%APPDATA%\Microsoft\Windows\SendTo\Plume.cmd` that launches the
     same command as autostart_command() plus `--import %1`. Removing
     the checkbox deletes the .cmd. No .lnk, no pywin32, no COM.
  3. Paste-as-path. If the clipboard is a quoted or raw filesystem
     path ending in .txt/.md and the file exists, _paste() offers
     "Open this file?" rather than inserting the path as source text.
     Decline → insert as text (today's behaviour).

Stale-import, replace-question, 2 MiB and character-limit behaviour
stay exactly as v1.28. Never auto-translate after import.

State: no new config keys except `send_to_shortcut` (bool, default
False). Performance: one extra argv parse at start; SendTo is a 1 KB
file; paste-as-path is a single os.path.isfile.

Explicitly not in this design: WM_DROPFILES, IDropTarget, tkinterdnd2,
cloud-placeholder files, Outlook attachments, .docx.

2.B  User Situation catalogue  (v1.33)
--------------------------------------
SITUATION_PRESETS (line 161) is still a five-line tuple. Conversation
presets (v1.19) already snapshot Situation *together with* direction,
form, gender, tones and writing profile. Users also want a *situation-
only* shortcut ("Guild raid chat", "School gate") without minting a
full conversation preset.

New config key `user_situation_presets`: a list of short strings,
normalised like keep-as-is (strip, drop blanks, casefold-unique, cap
MAX_USER_SITUATIONS = 12, MAX_SITUATION_CHARS = 80). Built-in names
are reserved: a user entry that casefold-matches a built-in is
dropped on load, so the menu cannot show two "Neighbour" rows.

Menu values: placeholder + built-ins + a separator-like label
"(My situations)" that is not selectable + user entries.
CTkOptionMenu has no real separator; use a disabled-looking prefix
"• " on user rows and ignore a click on the heading.

Actions, next to the existing menu (narrow, matching v1.30's
tightening):
  * "Save situation" — current situation_entry text, after
    normalisation. Duplicate (casefold) refused with an advisory, not
    silently skipped.
  * "Delete situation" — only user entries; built-ins cannot be
    deleted.

Persistence uses the v1.24 transactional pattern already used for
conversation presets: build a candidate config, save_config() first,
then publish to config_data and refresh the menu. ConfigError/OSError
surface on the advisory; never force=True.

No prompt change. Selecting a user situation still just writes the
string into situation_entry (_apply_situation_preset, line 3747).

Already present: input metrics (text_metrics, line 2462), study-sheet
export, textual diff, Copy as HTML. Remaining slice:

  1. A metrics label under the primary translation, refreshed by

  2. "Copy five" on the alternatives header: numbered plain text of

  3. Optional French typography, copy-time only, off by default.
     When the working result's target is French *and* the Settings

       * U+202F (narrow no-break space) before ; : ? !
       * "..." -> "…"

     Never sent to the model, never written into _current_main,
     never exported in the faithful Markdown diff. Speak uses the
     raw translation, matching v1.6's convention.

No python-docx. No RTF. Metrics stay Unicode code points + whitespace
tokens.

2.E  Cooperative cancel and local fallback  (v1.36)
---------------------------------------------------
Backoff is done (v1.17/v1.27). Streaming is excluded. Two remaining
resilience holes:

  1. Clear / close / a newer request only bump `_request_id`. The
     daemon thread keeps reading the socket; the user is billed for a
     translation they have abandoned. Fix: a per-request
     `threading.Event` stored on the app (`self._http_cancel`).
     `_http_post_json` takes an optional `cancel_event` and, in the
     wait_or_give_up path *and* after urlopen returns, raises a
     dedicated BackendError("cancelled") if the event is set. Clear,
     _on_close_destroy, and the start of a newer _translate/_speak
     set the event, then create a fresh one for the new request.
     urllib cannot abort a blocked read portably without closing the
     socket; we additionally wrap urlopen in a short join-able pattern
     only around the wait, not the read — documented limitation: a
     request already inside response.read() may still finish, but it
     will not be delivered (existing stale-id guard) and will not
     start a retry. That is the honest contract.

  2. Opt-in local fallback. New config `fallback_to_ollama` (bool,
     default False), Settings checkbox, disabled when TRAY-style
     extras are not the issue — when no ollama_model is set. After
     call_anthropic exhausts retries with a retryable failure, if the
     flag is on *and* the snapshot backend was anthropic, run_backend
     tries call_ollama once. Never the other way around (Ollama must
     not silently ship text to Anthropic). Surface a single advisory:
     "Claude was unavailable; translated with local Ollama." The
     result still goes through parse_translation_result. Privacy
     notice for Claude is unchanged; Ollama is local so no extra
     notice. One fallback attempt, no nested retry storm.

Not in this design: SSE parsers, stream:true, token-by-token UI
updates, cancelling ElevenLabs mid-download (can follow later on the
same Event).

SENDTO_SHORTCUT_NAME = "Plume.cmd"


def parse_import_path(argv) -> str:
    """Return the first --import argument, or "". Never raises."""
    args = list(argv or [])
    if "--import" in args:
        index = args.index("--import")
        if index + 1 < len(args):
            return args[index + 1]
    # A bare existing .txt/.md path is accepted so SendTo can pass %1.
    for item in args[1:]:
        if item.startswith("-"):
            continue
        if os.path.splitext(item)[1].casefold() in {".txt", ".md"}:
            return item
    return ""


def send_to_cmd_path() -> str:
    appdata = os.environ.get("APPDATA") or os.path.expanduser("~")
    return os.path.join(appdata, "Microsoft", "Windows", "SendTo",
                        SENDTO_SHORTCUT_NAME)


def set_send_to_shortcut(enabled: bool) -> None:
    """Create or delete the Explorer Send to command. Raises ConfigError."""
    path = send_to_cmd_path()
    if not enabled:
        try:
            os.remove(path)
        except FileNotFoundError:
            pass
        except OSError as exc:
            raise ConfigError("Could not remove the Send to shortcut.") from exc
        return
    folder = os.path.dirname(path)
    try:
        os.makedirs(folder, exist_ok=True)
        command = autostart_command().replace(" --start-minimised", "")
        body = (
            "@echo off\r\n"
            "start \"\" {command} --import \"%~1\"\r\n"
        ).format(command=command)
        with open(path, "w", encoding="ascii", newline="") as fh:
            fh.write(body)
    except OSError as exc:
        raise ConfigError("Could not write the Send to shortcut.") from exc


def looks_like_importable_path(text: str) -> str:
    """If *text* is one quoted/raw .txt/.md path that exists, return it."""
    candidate = (text or "").strip().strip('"')
    if os.path.splitext(candidate)[1].casefold() not in {".txt", ".md"}:
        return ""
    if os.path.isfile(candidate):
        return candidate
    return ""

MAX_USER_SITUATIONS = 12
MAX_SITUATION_CHARS = 80
USER_SITUATION_HEADING = "(My situations)"


def normalise_user_situations(value) -> list:
    """Short, unique situation labels; built-in names are reserved."""
    if isinstance(value, str):
        value = [line.strip() for line in value.splitlines()]
    if not isinstance(value, list):
        return []
    reserved = {item.casefold() for item in SITUATION_PRESETS}
    reserved.add(SITUATION_PRESET_PLACEHOLDER.casefold())
    reserved.add(USER_SITUATION_HEADING.casefold())
    seen = set()
    out = []
    for item in value:
        text = _safe_short_string(item, MAX_SITUATION_CHARS)
        if not text:
            continue
        key = text.casefold()
        if key in reserved or key in seen:
            continue
        seen.add(key)
        out.append(text)
        if len(out) >= MAX_USER_SITUATIONS:
            break
    return out


def situation_menu_values(user_items) -> list:
    values = [SITUATION_PRESET_PLACEHOLDER] + list(SITUATION_PRESETS)
    clean = normalise_user_situations(user_items)
    if clean:
        values.append(USER_SITUATION_HEADING)
        values.extend(clean)
    return values

_NBSP = "\u202f"  # narrow no-break space, French punctuation


def apply_french_typography(text: str) -> str:
    """Copy-time French punctuation only. Idempotent enough to unit-test.

    Does not invent words. Does not run on English. Callers must already
    know the target language is French.
    """
    if not isinstance(text, str) or not text:
        return text
    out = text.replace("...", "\u2026")
    out = re.sub(r"[ \t\u00a0\u202f]*([;:!?])", _NBSP + r"\1", out)
    # Straight quotes wrapping a short phrase → guillemets. Leave unmatched
    # quotes alone so a single inch-mark is not turned into an opener.
    out = re.sub(r"\"([^\"]{1,80})\"", r"« \1 »", out)
    return out


def format_five_alternatives(result) -> str:
    """Numbered translations only, no meaning checks, no finishing touch."""
    lines = []

        if translation.strip():
            lines.append("{}. {}".format(index, translation.strip()))
    return "\n".join(lines)

        def _new_http_cancel(self):
            """Invalidate in-flight HTTP waits; return a fresh event."""
            old = getattr(self, "_http_cancel", None)
            if old is not None:
                old.set()
            self._http_cancel = threading.Event()
            return self._http_cancel

# Call _new_http_cancel() at the start of _translate, _correct_then_translate
# and _speak, and from _clear / _on_close_destroy (alongside the id bump).

def _http_post_json(..., cancel_event=None):
    # inside wait_or_give_up, before time.sleep:
        if cancel_event is not None and cancel_event.is_set():
            raise BackendError("The request was cancelled.")
    # after a successful urlopen, before json.loads:
        if cancel_event is not None and cancel_event.is_set():
            raise BackendError("The request was cancelled.")

# Thread the event through call_anthropic / call_ollama / run_backend
# via config_snapshot["_cancel_event"] so the worker does not close over
# the widget. Pop it before any persistence.

def run_backend(config_snapshot, system_prompt, user_text):
    backend = normalise_backend(config_snapshot.get("backend"))
    try:
        if backend == "ollama":
            return call_ollama(config_snapshot, system_prompt, user_text)
        return call_anthropic(config_snapshot, system_prompt, user_text)
    except BackendError as exc:
        if (
            backend != "ollama"
            and config_snapshot.get("fallback_to_ollama")
            and (config_snapshot.get("ollama_model") or "").strip()
            and "cancelled" not in str(exc).casefold()
        ):
            text = call_ollama(config_snapshot, system_prompt, user_text)
            return text, "fallback-ollama"
        raise

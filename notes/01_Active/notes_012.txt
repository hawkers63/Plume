CRITICAL

C1. History window clobbers translations saved while it is open
----------------------------------------------------------------
Invariant broken: "favourited items must not be silently deleted"; also
ordinary history loss.

HistoryDialog loads once (`self._entries = load_history()`, line 2514)
and `_persist` (line 2692) writes *that list* back. PlumeApp._save_to_history
(line 4052) and _favourite_current_result (line 4071) load-modify-save
independently. The dialog's own docstring (lines 2500–2502) claims the
two writers "never need to share in-memory state". That is false: they
share the file, and the dialog holds a stale snapshot.

Reproduction:
  1. Enable local history. Open History. Leave it open.
  2. Translate a new phrase in the main window.
     _save_to_history inserts the entry on disk.
  3. In the History window, favourite or delete any *older* card.
     _persist writes the snapshot from step 1.
  4. The translation from step 2 is gone. If the user had favourited
     it from the main panel between 2 and 3, that favourite is gone too.

The same last-writer-wins applies in reverse: History open, user
favourites a card, a translation completes and save_history writes a
list that still has the un-favourited flag.

Risk: silent data loss of the one store Plume treats as durable. Opt-in
history being off by default limits blast radius, but this is exactly
the path a daily user with history on will hit.

C2. Reopen from History does not supersede an in-flight translation
-------------------------------------------------------------------
Invariant broken: stale-request protection.

_reopen_history_entry (line 3530) writes the input box, situation and
result cards but does **not** increment `_request_id` or `_speech_request_id`,
and does not re-enable/disable the Translate lock. HistoryDialog._reopen
(line 2635) then destroys the dialog.

Reproduction:
  1. Translate a long phrase (Claude in flight, Translate disabled).
  2. Open History, Reopen an older entry.
     UI now shows the old phrase and its five alternatives.
  3. The in-flight worker completes. `_deliver` (line 3943) sees the
     *same* `_request_id` it was born with, so it is not stale.
  4. The reopened result is replaced by the late translation. The
     input box is *not* overwritten (snap_text check at 3972) but the
     right-hand pane and history-save are. The user is looking at a
     translation of a different phrase than the one in the left pane,
     with only the "Generated for an earlier message" advisory if the
     reopened source text happened to differ — and if they reopened
     an entry whose source accidentally equals the in-flight source,
     there is no advisory at all.

Clear and window-close *do* bump the id. Reopen is the missing sibling.

MODERATE

M1. Settings save wipes presets created while Settings is open
--------------------------------------------------------------
SettingsDialog copies config at open (`self._config = dict(config)`,
line 2153 — a *shallow* copy). `_save_conversation_preset_dialog`
(line 3243) rebinds `config_data["conversation_presets"]` to a new
list and writes it immediately. Settings is not grab-set, so Save
preset still works with Settings open.

On Settings Save (line 2483) `self._config["conversation_presets"]`
still points at the list from dialog-open. That list is written back
and the newly named preset disappears.

M2. `_speak` bumps `_speech_request_id` before it is allowed to start
---------------------------------------------------------------------
Lines 3567–3585: the counter increments, *then* the missing-key return
and the privacy `askokcancel`. Cancelling the privacy notice, or
clicking Speak with no key configured, leaves the previous in-flight
TTS worker stale. Its audio is dropped on `_deliver_speech` even
though the user did not start a replacement.

M3. Correction preservation warnings are never seen
---------------------------------------------------
`_deliver_correction` (3848–3851) puts correction notes on the advisory,
then immediately calls `_translate()` which does `self.advisory.grid_remove()`
at line 3915. A failed keep-as-is round-trip during Correct English is
silent; auto-translate proceeds on text that may have dropped a name.

M4. Correction failure leaves "Use as input" disabled
-----------------------------------------------------
`_correct_then_translate` disables `use_as_input_btn` (3789).
`_deliver_correction` on error (3825–3832) restores Translate, Correct
and Reply, but not Use as input. After a failed correction the previous
result is still on screen but the button stays dead until the next
successful translate.

M5. Favourite and Export bind to the *live* input, not the translated source
----------------------------------------------------------------------------
`_save_to_history` correctly uses `snap_text`. `_favourite_current_result`
(4107) and `_export_current_result` (4140) use `self._input_text()` /
`self._situation_text()`. If the user has edited the left pane since
the result arrived — including the C2 advisory path — a favourite is
stored as (new source, old translation). Corrupt study data.

There is no `self._current_source` today; `_current_result` does not
carry the source either (make_history_entry puts it on the history
record only).

M6. TTS temp-file leak on Windows
---------------------------------
`_play_wav_bytes` (3652) plays with `winsound.SND_FILENAME | SND_ASYNC`.
The next Speak / Clear / close calls `_stop_speech` (SND_PURGE) then
`_cleanup_tts_file`. On Windows the file handle is often still held
for a beat after PURGE; `os.remove` raises OSError, which is swallowed,
and `_tts_temp_path` is set to None anyway (3647–3650). The WAV is
leaked in %TEMP%\plume_tts_*.wav. Repeated Speak clicks accumulate
files. Rapid Speak also fires parallel ElevenLabs workers (M12).

M7. New translation does not stop the previous playback
-------------------------------------------------------
`_clear_results` stops speech; `_render_result` (4023) does not. A
Speak of alternative 3, then a new Translate, leaves the old audio
playing over the new cards. Close-to-tray (M-minor below) has the
same gap.

M8. HTTPError body is not consumed before a retry
-------------------------------------------------
`_http_post_json` (1578) catches HTTPError, possibly sleeps, and
retries. The error response's `fp` is never read or closed. urllib
documents that this can leak the socket. Four attempts × a busy
session is enough to matter. 401/403 already avoid the retry path.

M9. Token restore skips `language_note` and `notes`
---------------------------------------------------
`restore_result_tokens` (1002–1020) restores main + five alternatives
only. `language_note` and `notes` are parsed earlier and can still
contain `⟦PH0⟧`. Those strings are shown on the advisory strip
(`advisory_text_from_result`). The missing-token warning is generic
and does not leak source, but a *present* token in a note *does*
expose the marker, and a model that echoes a name into `notes`
bypasses masking entirely. Also no post-restore scan for leftover
`_PH_TOKEN_RE` matches on the visible fields.

M10. Favourites with ≠ 5 alternatives are dropped, then deleted on save
-----------------------------------------------------------------------
`normalise_history_entry` (648–649) returns None unless
`len(clean_variations) == VARIATION_COUNT`. A hand-edit, a partial
write, or a future schema slip drops a *favourite* on load. The next
`save_history` (History persist, or a new translation) writes the
filtered list. The favourite is gone from disk. load_history itself
is defensive; the combination with persist is not.

M11. Autostart registry is written before config save
-----------------------------------------------------
SettingsDialog._save (2461–2465) calls `set_launch_at_sign_in` *then*
`save_config`. If the user declines the damaged-file recovery prompt,
the HKCU Run value already changed and `launch_at_sign_in` in the
file did not. `launch_at_sign_in_is_set()` exists (line 507) but is
never used to reconcile the checkbox with the registry.

M12. Speak is not serialised
----------------------------
Unlike Translate, Speak never disables its buttons. Each click starts
another ElevenLabs thread. Only the latest `_speech_request_id` plays;
the rest are paid for and discarded. Combined with M6 this is the
leak-and-spend path.

M13. HTML clipboard: NULL lock and failed SetClipboardData
----------------------------------------------------------
`copy_html_to_windows_clipboard` (1967–1981) `GlobalAlloc`s then
`GlobalLock`s without checking the lock pointer (memmove of NULL is a
process crash) and does not `GlobalFree` if `SetClipboardData` fails
(ownership does not transfer; the HGLOBAL leaks). Rare, but this is
native code with no Python except around the inner block covering
Lock. The outer `except Exception` will not catch an access violation.

5. What was checked and is sound
------------------------------------------------------------------------
* `_request_id` / `_speech_request_id` monotonic `!=` guard on
  `_deliver`, `_deliver_speech`, `_deliver_correction`. Clear and
  window-destroy bump both. Ctrl+Enter respects the disabled Translate
  button. Correction uses the same lock.
* Worker callbacks: `winfo_exists()` then `after(0, …)` with
  `tk.TclError` swallowed on Settings detect, translate, correct, TTS.
* `save_config` / `save_history`: tempfile → flush → fsync → replace;
  refuse malformed unless `force=True`.
* `parse_translation_result`: empty / non-object / wrong arity / missing
  meaning checks / duplicates-after-normalise / same source and target /
  forced-direction mismatch all raise. Trailing prose fails `json.loads`.
  210 tests cover this.
* `protect_text` extra_terms longest-first, `re.escape` in
  `keep_as_is_pattern`. Missing-token warning does not echo source
  (`test_warning_does_not_leak_original_value`).
* `format_status` / `mask_api_key` / BackendError paths: no source in
  the tested strings. Ollama `error` field is not interpolated.
* Tray callbacks hop to Tk via `after(0, …)`. Autostart refuses to
  enable without pystray+Pillow, so login cannot hide a window with
  no icon.
* `result_is_stale` is a pure `!=`; Python ints do not overflow.

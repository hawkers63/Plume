2. Bugs by severity
-------------------

CRITICAL
  None.

MODERATE

  M1 - Undo Clear stays armed after a later Translate/Correct and can wipe
       the new result
  Failure point: PlumeApp._clear (sets undo enabled), _translate /
  _correct_then_translate (do not disarm undo), _deliver /
  _deliver_correction (do not disarm undo), _undo_clear (~6805)
  Why: Clear takes a snapshot and enables Undo. A subsequent successful
  Translate or Correct English leaves that snapshot and the Undo button
  armed. Clicking Undo Clear then restores the pre-Clear pane and overwrites
  the newer accepted result. Undo also stays clickable while Translate is
  in flight (undo_clear_btn is never disabled with the other action
  buttons), so the restored pane can be immediately overwritten when the
  in-flight _deliver lands (request id is deliberately not bumped on Undo).
  Insertion point: disarm undo when a new request starts and when a new
  result is accepted (and optionally while in flight).

MINOR

  m1 - _reopen_history_entry bumps request/speech ids and stops playback but
       does not call _new_http_cancel() (unlike _clear / _on_close_destroy).
       Delivery is still dropped by result_is_stale; only retry/cancel waits
       are less consistent. plume.py ~7117.

  m2 - Clear snapshot does not capture finishing-touch / sign-off / MMORPG
       picks or favourite state. Undo restores main+alternatives via
       _render_result but leaves touches at None and favourite unstarred.
       Acceptable if Undo is defined as "content only"; surprising if the
       user had a touch selected. _take_clear_snapshot ~6751.

3. Proposed snippets
--------------------

M1 - At the start of _translate, after the busy-guard, invalidate Undo:

            # A new request supersedes "Undo Clear": the snapshot is from
            # before this work and must not wipe the result we are about
            # to accept.
            self._clear_snapshot = None
            self._set_undo_clear_enabled(False)

  Same two lines at the start of _correct_then_translate after its busy-guard
  (before the worker is started).

  Optional hardening in _deliver / _deliver_correction after the stale-id
  check passes (accepted result path), repeat the same two lines so any
  future entry point that starts work without clearing the snapshot is
  still safe.

  Optional: in _translate / _correct_then_translate when disabling action
  buttons, also:
            self._set_undo_clear_enabled(False)
  (already implied if the snapshot is cleared at request start).

m1 - In _reopen_history_entry, immediately after bumping speech/request ids:
            self._new_http_cancel()

m2 - Only if product intent is full UI restore: extend _take_clear_snapshot
     with finishing_touch / casual_signoff / mmorpg / favourited values and
     re-apply them in _undo_clear after _render_result. Otherwise document
     that Undo restores text only.

Executive summary
-----------------
Plume is in generally good shape for a compact single-file CustomTkinter app. The deterministic translation core is unusually well covered: parsing, placeholder preservation, config hardening, backend error privacy, stale translation delivery, finishing touches, gender prompting, TTS wrapping, and history persistence all have focused tests.

The main risks are concentrated in newer GUI-level paths that are not covered by the test suite: result advisory display, speech playback state, and history entry shape. The most important behavioural bug is that model notes and placeholder warnings are rendered only inside the opt-in history save method. Because local history is off by default, default users can miss low-confidence language notes or protected-placeholder warnings entirely.

The rest of the findings are incremental rather than architectural: make history entries preserve all result metadata, protect the app from stale/out-of-order TTS playback, make generic HTTP errors service-aware, expose the existing max-input limit in Settings or adjust the message, and update documentation/config examples to match the features already landed in v1.5-v1.7.

1. Moderate - Result advisories are skipped when local history is disabled
---------------------------------------------------------------------------
Location:

- C:\Plume\plume.py:2345-2347
- C:\Plume\plume.py:2416-2442

Problem:

Plume renders a completed result, then calls _save_to_history(). That method immediately returns when save_local_history is false:

    if not self.config_data.get("save_local_history"):
        return

The advisory rendering for result["language_note"] and result["notes"] sits after that return. Since save_local_history defaults to false, language uncertainty notes and placeholder-loss warnings are invisible for default users.

Impact:

- Low-confidence auto-detection can be hidden.
- Placeholder preservation warnings from restore_result_tokens() can be hidden.
- Users may copy/send a translation without seeing that protected material may have been dropped.

Targeted fix:

Separate advisory display from history persistence. Keep _save_to_history() responsible only for optional disk persistence, and call a small advisory renderer for every successful result.

Insertion point:

- Add advisory_text_from_result() in C:\Plume\plume.py below format_language_label() at about line 1209, before mask_api_key().
- Add _show_result_advisories() inside class PlumeApp below _render_result() at about line 2415.
- In _deliver(), after self._render_result(data) and before self._save_to_history(...), call self._show_result_advisories(data).
- Remove the advisory block from _save_to_history().

Proposed code:

```python
def advisory_text_from_result(result: dict) -> str:
    """Return the advisory text that should be shown for a translation result.

    The language note and optional result notes are display concerns, not
    history-persistence concerns. Keeping this helper pure makes it easy to
    test that placeholder warnings and low-confidence notes are shown even
    when local history is disabled.
    """
    notes = [result.get("language_note", "")]
    notes.extend(result.get("notes", []))
    return "  •  ".join(
        note.strip()
        for note in notes
        if isinstance(note, str) and note.strip()
    )
```

```python
def make_history_entry(source_text, result, situation="") -> dict:
```

3. Moderate - History loading accepts any dict, so malformed entries can crash Reopen
------------------------------------------------------------------------------------
Location:

- C:\Plume\plume.py:346-363
- C:\Plume\plume.py:2086-2100
- C:\Plume\plume.py:2401-2414

Problem:

load_history() filters only for isinstance(entry, dict). The History window can therefore contain entries missing "main_translation" or "variations". Most card rendering uses .get(), but Reopen passes the raw entry into _render_result(), which indexes result["main_translation"] and result["variations"]. A partially malformed plume_history.json can therefore crash the UI when Reopen is clicked.

Impact:

- One bad history entry can break the Reopen workflow.
- The malformed-file protection is strong at file level, but weak at entry-shape level.

Targeted fix:

Normalise history entries as they are loaded. Keep the rules modest: require only a renderable main_translation and a list of variation dicts with usable translation and english_meaning_check strings. Preserve unknown keys by copying only the fields Plume understands.

Insertion point:

- Add normalise_history_entry() below make_history_entry() in C:\Plume\plume.py.
- Update load_history() at about line 363 to use the helper.

Proposed code:

```python
def normalise_history_entry(entry) -> dict | None:
    """Return a renderable history entry, or None if the entry is unusable.

    The history file is user-local and may have been edited or produced by an
    older Plume version. This keeps the History window resilient without
    rewriting the file during load.
    """
    if not isinstance(entry, dict):
        return None

    main = entry.get("main_translation")
    variations = entry.get("variations")
    if not isinstance(main, str) or not main.strip():
        return None
    if not isinstance(variations, list):
        return None

    clean_variations = []
    for item in variations:
        if not isinstance(item, dict):
            continue
        translation = item.get("translation")
        meaning = item.get("english_meaning_check")
        if isinstance(translation, str) and translation.strip() and isinstance(meaning, str) and meaning.strip():
            clean_variations.append(
                {
                    "translation": translation.strip(),
                    "english_meaning_check": meaning.strip(),
                }
            )

    if len(clean_variations) != VARIATION_COUNT:
        return None

    return {
        "id": str(entry.get("id") or uuid.uuid4().hex),
        "timestamp": str(entry.get("timestamp") or ""),
        "source_language": entry.get("source_language", ""),
        "target_language": entry.get("target_language", ""),
        "language_confidence": entry.get("language_confidence", "low"),
        "language_note": _safe_short_string(entry.get("language_note", "")),
        "source_text": entry.get("source_text", ""),
        "situation": _safe_short_string(entry.get("situation", "")),
        "main_translation": main.strip(),
        "variations": clean_variations,
        "notes": _safe_string_list(entry.get("notes", [])),
        "favourite": bool(entry.get("favourite")),
    }
```


```python
def _http_post_json(url, payload, headers, timeout, service_name="backend"):
    """POST *payload* as JSON and return the decoded JSON response.

    The service name is used only for safe, generic diagnostics; backend detail
    text is still not displayed because it may contain prompt fragments.
    """
    data = json.dumps(payload).encode("utf-8")
    request = urllib.request.Request(url, data=data, headers=headers, method="POST")
    try:
        with urllib.request.urlopen(request, timeout=timeout) as response:
            body = response.read().decode("utf-8")
    except urllib.error.HTTPError as exc:
        raise BackendError(_friendly_http_message(exc.code, service_name))
    except urllib.error.URLError as exc:
        raise BackendError(
            "Could not reach the translation backend. Please check your "
            "connection and try again. ({})".format(_reason_text(exc))
        )
    except (TimeoutError, OSError):
        raise BackendError(
            "The translation backend did not respond in time. Please try again."
        )
    try:
        return json.loads(body)
    except ValueError:
        raise BackendError("The backend returned a response that could not be read.")
```

```python
def _friendly_http_message(code, service_name="backend") -> str:
    """Return a safe user-facing message for a backend HTTP status."""
    if code in (401, 403):
        return "{} rejected the request. Please check its credentials or settings.".format(
            service_name
        )
    if code == 404:
        return (
            "The requested model or endpoint was not found. Please check the "
            "model name in Settings."
        )
    if code == 429:
        return "{} is rate limiting requests. Please wait and retry.".format(service_name)
    if 500 <= code < 600:
        return "The translation service reported a temporary error. Please retry."
    return "The request failed (HTTP {}). Please try again.".format(code)
```

```python
def coerce_positive_int(value, default: int) -> int:
    """Return *value* as a positive integer, or *default* if it is invalid."""
    try:
```

Additional observations

Strengths
---------
- The response contract is strict and well defended. parse_translation_result() rejects malformed JSON, wrong top-level type, empty primary text, wrong variation count, duplicate alternatives, invalid language pairs, and forced-direction mismatch.
- Placeholder protection and restoration are privacy-conscious. The warning intentionally avoids echoing protected values.
- Config and history saves use atomic temp-file replacement and malformed-file protection.
- Translation worker delivery has a stale-request guard, protecting Clear/later requests/window close from late background callbacks.

- The test suite is compact but broad for deterministic logic.

- Advisory rendering when save_local_history is false.

2. History entries now preserve language_confidence, language_note and notes.
   Reopened entries no longer need to invent a low-confidence fallback for new
   records.

3. load_history() now normalises entry shape via normalise_history_entry().
   Unusable local records are skipped during load rather than being allowed to
   crash the Reopen path later.

4. Speak/TTS requests now use a dedicated _speech_request_id stale guard.
   A slower old speech request can no longer interrupt or replace the audio
   from a newer Speak click. Temporary TTS files are also cleaned up on
   replacement, Clear and window close.

5. Backend HTTP messages are service-aware. The shared POST helper now receives
   a service_name so Ollama HTTP errors do not mention Claude.

6. Settings now exposes the existing max_input_chars value as "Maximum message
   length", backed by the shared coerce_positive_int() helper.

7. Documentation was refreshed: README now describes local history, Reopen and
   ElevenLabs Speak accurately, and plume_config.example.json matches
   DEFAULT_CONFIG.

### Per-Conversation Phrasebook

I am pleased to introduce the per-conversation phrasebook as an optional, lightweight panel. This feature will coexist with the current Situation and Tones controls, maintaining a straightforward list of source → note pairs that users can modify and insert into the input box. It is important to note that this phrasebook is not transmitted to the model; it serves solely as a local reference.

This feature represents a small, self-contained extension that leverages existing patterns (such as dialogs, clipboard functionality, and insertion logic) and does not interfere with the translation pipeline.

### Design Overview

**Storage:**

A new key, "active_phrasebook," will be added to the configuration snapshot. This key will not persist across application launches unless the user opts for this feature; we can store it as a temporary property of PlumeApp.

To maintain simplicity, we will represent it as a list of dictionaries formatted as {"source": "...", "note": "..."}.

**UI:**

A compact “Phrasebook” button will be positioned adjacent to the Situation row or within the left pane.

Upon clicking this button, a non-modal PhrasebookDialog will open (similar to the SlangReferenceDialog).

The dialog will feature a scrollable list of entries alongside a text entry and button for adding new pairs.

Each entry will include an “Insert” button, which will place the source phrase at the current caret position in the input box.

**Interaction:**

The phrasebook will be editable; users will have the capability to add, edit, or delete entries.

Entries will be stored only in memory for the current session. While persistence may be implemented in future versions, the initial release will maintain an ephemeral nature.

```python
class PhrasebookDialog(ctk.CTkToplevel):
    """Editable per-conversation reference list; never sent to the model."""

    def __init__(self, master):
        super().__init__(master)
        self.title("{} — Phrasebook".format(APP_NAME))
        self.geometry("520x480")
        self.minsize(400, 360)
        self.transient(master)
        self.grid_columnconfigure(0, weight=1)
        self.grid_rowconfigure(1, weight=1)

        # Data: store as list of {"source": str, "note": str}
        self._entries = master._phrasebook_entries  # shared list

        # Top: add new entry
        add_frame = ctk.CTkFrame(self, fg_color="transparent")
        add_frame.grid(row=0, column=0, sticky="ew", padx=12, pady=(12, 4))
        add_frame.grid_columnconfigure(1, weight=1)
        ctk.CTkLabel(add_frame, text="Add phrase:").grid(row=0, column=0, padx=(0, 6))
        self.source_entry = ctk.CTkEntry(add_frame, placeholder_text="source phrase")
        self.source_entry.grid(row=0, column=1, sticky="ew", padx=6)
        self.note_entry = ctk.CTkEntry(add_frame, placeholder_text="translation / note")
        self.note_entry.grid(row=0, column=2, sticky="ew", padx=6)
        ctk.CTkButton(add_frame, text="Add", width=60, command=self._add_entry).grid(row=0, column=3, padx=(6, 0))

        # List of entries (scrollable frame)
        self.list_frame = ctk.CTkScrollableFrame(self)
        self.list_frame.grid(row=1, column=0, sticky="nsew", padx=12, pady=4)
        self.list_frame.grid_columnconfigure(0, weight=1)

        self._refresh_list()

    def _refresh_list(self):
        for child in self.list_frame.winfo_children():
            child.destroy()
        if not self._entries:
            ctk.CTkLabel(self.list_frame, text="No entries yet.", text_color="gray60").grid(row=0, column=0, pady=8)
            return
        for idx, entry in enumerate(self._entries):
            card = ctk.CTkFrame(self.list_frame, border_width=1)
            card.grid(row=idx, column=0, sticky="ew", pady=4)
            card.grid_columnconfigure(0, weight=1)

            # Source + note
            label_text = entry.get("source", "").strip()
            if entry.get("note"):
                label_text += " — " + entry["note"].strip()
            ctk.CTkLabel(card, text=label_text, wraplength=380, justify="left").grid(
                row=0, column=0, sticky="w", padx=8, pady=6
            )

            # Buttons
            btn_frame = ctk.CTkFrame(card, fg_color="transparent")
            btn_frame.grid(row=0, column=1, padx=6, pady=6)
            ctk.CTkButton(
                btn_frame, text="Insert", width=70,
                command=lambda src=entry.get("source", ""): self._insert_source(src)
            ).grid(row=0, column=0, padx=(0, 4))
            ctk.CTkButton(
                btn_frame, text="Delete", width=70, fg_color="gray30",
                command=lambda idx=idx: self._delete_entry(idx)
            ).grid(row=0, column=1)

    def _add_entry(self):
        source = self.source_entry.get().strip()
        note = self.note_entry.get().strip()
        if not source:
            return
        # Avoid duplicates (simple)
        if any(e.get("source", "").casefold() == source.casefold() for e in self._entries):
            self.source_entry.delete(0, "end")
            self.source_entry.insert(0, "(already exists)")
            return
        self._entries.append({"source": source, "note": note})
        self.source_entry.delete(0, "end")
        self.note_entry.delete(0, "end")
        self._refresh_list()

    def _delete_entry(self, idx):
        if 0 <= idx < len(self._entries):
            del self._entries[idx]
            self._refresh_list()

    def _insert_source(self, source):
        """Insert the source phrase into the main input box at caret."""
        if not source:
            return
        # Use the same helper as slang insertion (reuse logic)
        try:
            self.master._insert_phrasebook_source(source)
        except ValueError as exc:
            messagebox.showinfo("Phrasebook", str(exc), parent=self)

def _open_phrasebook(self):
    existing = getattr(self, "_phrasebook_dialog", None)
    if existing is not None and existing.winfo_exists():
        existing.lift()
        existing.focus()
        return
    self._phrasebook_dialog = PhrasebookDialog(self)

# Insertion helper:
def _insert_phrasebook_source(self, source):
    """Insert the phrasebook source into the input box, respecting character limit."""
    text_widget = find_slang_text_widget(self.input_box)
    if text_widget is None:
        raise ValueError("The input box is not ready.")
    current = self._input_text()
    offset = len(text_widget.get("1.0", "insert"))
    limit = coerce_positive_int(self.config_data.get("max_input_chars"), DEFAULT_MAX_INPUT_CHARS)
    # We use the same insertion logic as slang_insertion but we want to insert the exact source phrase.
    # We can call slang_insertion with term=source, but it will add spaces only at alnum boundaries.
    # We'll copy the logic or reuse it with a small adjustment.
    # For simplicity, we can directly insert without automatic spacing; the user can edit.
    # Let's use a simpler insertion: just insert the text at caret.
    candidate = current[:offset] + source + current[offset:]
    if len(candidate) > limit:
        raise ValueError("Insertion would exceed the character limit.")
    text_widget.insert("insert", source)
    self._on_input_change()
    text_widget.focus_set()
```

### Benefits and Limitations

**Benefits:**

- Provides a context-sensitive reference that remains with the current conversation.
- Minimises the need to switch to the global glossary or slang window for frequently used terms.
- Offers a simple, ephemeral, and non-intrusive feature that users may choose to ignore entirely.

**Limitations:**

- Entries are not retained across sessions (unless a save option is added in the future).
- Does not include automatic lookup; it relies on a manual list.

This implementation introduces approximately 150 lines of new code, effectively reusing existing patterns. It integrates seamlessly with the current codebase and aligns with Plume’s philosophy of incremental, user-focused development.

### Persist The Phrasebook

Persisting the phrasebook represents a logical progression in our development process. There are two distinct, low-overhead approaches, each with unique advantages. I will outline both methods with concrete code examples, followed by my recommendation based on Plume’s current architecture.

**Path 1: Embedding the Phrasebook Within Conversation Presets (Recommended)**  
This option offers a cohesive integration. A conversation preset already captures essential elements such as direction, formality, tone, situational context, and writing profile; incorporating a phrasebook transforms the preset into a comprehensive context snapshot. When applying a preset, all necessary components for that specific conversation, including domain-specific vocabulary, are readily available.

**Required Modifications**  
1. **Add a Normalisation Helper for Phrasebooks**  
In the constants section (approximately line 500), include the following:

```python
PHRASEBOOK_MAX_ENTRIES = 30
PHRASEBOOK_MAX_SOURCE_CHARS = 80
PHRASEBOOK_MAX_NOTE_CHARS = 80

def normalise_phrasebook(value) -> list:
    """Return a clean list of {"source": ..., "note": ...} pairs."""
    if not isinstance(value, list):
        return []
    out = []
    seen = set()
    for item in value:
        if not isinstance(item, dict):
            continue
        source = str(item.get("source") or "").strip()
        note = str(item.get("note") or "").strip()
        if not source:
            continue
        if len(source) > PHRASEBOOK_MAX_SOURCE_CHARS or len(note) > PHRASEBOOK_MAX_NOTE_CHARS:
            continue
        key = source.casefold()
        if key in seen:
            continue
        seen.add(key)
        out.append({"source": source, "note": note})
        if len(out) >= PHRASEBOOK_MAX_ENTRIES:
            break
    return out
```

**Path 2: Standalone `plume_phrasebooks.json` File**  
This approach maintains the phrasebook's independence from presets, allowing it to be shared across various presets or utilised without any preset at all. While this method requires more effort, it provides enhanced flexibility.

**Required Modifications**  
1. **Add Path & File Helpers**  
In the configuration section, introduce:

```python
PHRASEBOOK_FILENAME = "plume_phrasebooks.json"

def phrasebook_path() -> str:
    return os.path.join(config_dir(), PHRASEBOOK_FILENAME)

def load_phrasebook() -> list:
    """Load the shared phrasebook; returns [] if missing or damaged."""
    path = phrasebook_path()
    if not os.path.exists(path):
        return []
    try:
        with open(path, "r", encoding="utf-8") as fh:
            data = json.load(fh)
    except (OSError, ValueError):
        return []
    return normalise_phrasebook(data if isinstance(data, list) else [])

def save_phrasebook(entries, force: bool = False) -> None:
    """Atomically write the phrasebook to disk."""
    path = phrasebook_path()
    # Optional: add malformed check similar to save_config
    if not force and _is_existing_file_malformed(path, expected_type=list):
        raise ConfigError("The phrasebook file appears damaged; use force=True to replace.")
    os.makedirs(os.path.dirname(path), exist_ok=True)
    tmp_path = path + ".tmp"
    payload = json.dumps(entries, indent=2, ensure_ascii=False)
    with open(tmp_path, "w", encoding="utf-8") as fh:
        fh.write(payload)
        fh.flush()
        os.fsync(fh.fileno())
    os.replace(tmp_path, path)
```

2. **Load on Application Start**  
In `PlumeApp.__init__`, load the shared phrasebook:

```python

3. **Auto-Save (or Manual Save) on Changes**  
Two options are available:

- **Option A**: Auto-save on every change (simpler, but frequent disk writes):  
Modify `PhrasebookDialog._add_entry` and `_delete_entry` to invoke `save_phrasebook(self._entries)` after each modification.

- **Option B**: Explicit “Save” button (provides user control, aligns with existing patterns):

**Comparison & Recommendation**  
| Aspect | Embedded in Presets | Standalone File |
|--------|---------------------|------------------|
| Persistence | Saved as part of `conversation_presets` in `plume_config.json` | Separate `plume_phrasebooks.json` file |
| Granularity | Tied to a specific preset — ideal for domain-specific conversations | Shared globally — suitable for a “personal dictionary” |
| Code Impact | Minimal: extends three existing functions | New file I/O functions, load/save integration |
| UX Clarity | “This preset remembers my key terms” | “I have a separate phrasebook that stays with me” |
| Conflict Resolution | Presets manage duplicates/names; phrasebooks inherit that | Requires separate handling for merging/editing |
| Roadmap Fit | Natural extension of the v1.19 “presets” feature | Feels like a new concept (a library) |

**My Recommendation: Embed in Presets**  
**Reasons:**

- **No New Files**: Eliminates the need to manage additional JSON files and mitigates the risk of file corruption.
- **Semantic Alignment**: A conversation preset already represents a “full context” snapshot. Integrating the phrasebook completes this package, encompassing tone, formality, situation, and vocabulary — precisely what a user seeks when transitioning from “Work email” to “Guild raid chat”.
- **Reduced UI Clutter**: There is no requirement for a separate “Save” button or an explanation of an additional persistence layer.
- **Preserved Ephemerality**: If a user opts not to save a preset, the phrasebook remains transient (cleared on `_clear`), aligning with the current behaviour of tones and writing profiles.

Should a user later desire a shared phrasebook across presets, I could implement an “Import from preset” or “Export to file” feature as a secondary enhancement.

**Testing Considerations**  
For the embedded approach, update the existing preset tests to:

- Ensure `normalise_conversation_preset` accurately normalises the phrasebook key.
- Verify that a phrasebook saved with a preset survives the `save_config/load_config` round-trip.
- Test the cap (`PHRASEBOOK_MAX_ENTRIES`) and the de-duplication process.

For the file-based approach, introduce new unit tests for `load_phrasebook` and `save_phrasebook` using a temporary directory, reflecting the existing `TestConfig` and `TestHistoryPersistence` classes.

Both approaches are valid. If a global, always-available dictionary is preferred, the file approach is superior. However, for context-specific vocabulary that accompanies the conversation preset, the embedded approach is cleaner and more cohesive.

Given Plume’s existing preset-centric design, I strongly advocate for embedding, as it represents a natural and almost seamless extension of the current feature set.

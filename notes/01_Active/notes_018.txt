1. Executive summary
------------------------------------------------------------------------
Two defects the user named, then nothing from the standing five-item
brief that is not already shipped.

  A. The French slang reference (v1.34) can open and still look empty.
     That is a presentation bug, not a missing catalogue. Eighteen
     records exist in SLANG_CATALOGUE (line 364); the Settings
     "Glossary" box is a different feature (preferred translations)
     and never showed slang. Fix the window so the term list is
     actually visible, then ship the next editorially reviewed batch
     from notes_014's "French Slang Words" section so the category
     the user is looking for has substance.

  B. The three copy-time dropdowns are still the first-ship minima:
     finishing touches 7 terms, casual sign-off 2, MMORPG 6 (plus
     None). The user wants more text-emote / append-tag choices in
     each, without folding the slang reference into those menus.

Recommended order:

  v1.40  Make SlangReferenceDialog visible and populated (always-on-
         top, deferred refresh, list gets the height). Discoverability
         caption so it is not confused with Settings → Glossary.
  v1.41  Expand the three append-tag catalogues under the existing
         disjointness and "suffix-safe" rules, with English glosses.
  v1.42  Second slang-reference batch (vocabulary/phrases), pending
         items still held back.

UX rationale: a conversation helper that advertises slang but shows a
blank middle pane, or two sign-off words, will be judged unfinished
regardless of how complete the translator pipeline is. These are
catalogue and window-lifecycle fixes, not new architecture.

2.A  Slang reference not displaying  (v1.40)
--------------------------------------------
What exists: toolbar-adjacent button "French slang…" (line 4094) opens
SlangReferenceDialog (line 3692). Search, category filter, 18 cards,
local draft. No network. Tests cover search/insert, not window stacking.

Three independent reasons the user can click the button and see "no
glossary":

  1. Always-on-top. PlumeApp._apply_always_on_top (line 3923) sets
     -topmost on the main window. The slang dialog is only
     transient(master). A non-topmost transient often maps *behind* a
     topmost parent on Windows 11. _open_slang_reference (line 4553)
     lifts a *reused* window but never sets -topmost, and a first-time
     open does not lift at all. Symptom: click, nothing appears;
     Alt+Tab may reveal it.

  2. Results list built before the scrollable frame is mapped.
     __init__ calls self._refresh() synchronously (line 3769) while
     constructing CTkScrollableFrame. CustomTkinter's inner canvas
     often still has height 0; child cards are created and never
     laid out. The footer can still read "18 matching term(s)."
     Symptom: search box, category, draft, and a blank hole where
     the glossary should be.

  3. Height split. grid_rowconfigure(2, weight=1) *and*
     grid_rowconfigure(4, weight=1) give the catalogue and the draft
     equal stretch. Chrome (search, filter, captions, buttons) plus
     a 720px default leaves the term list a sliver. Symptom: "the
     slang section isn't there" — it is a few pixels tall.

  4. Discoverability (not a crash). Settings still has "Glossary"
     (line 3311), which is translation_glossary. Users looking for
     "slang words glossary" in Settings will not find SLANG_CATALOGUE.
     The 95-row "French Slang Words" attachment section was never a
     category name in the filter (categories are Texting, Greetings,
     Reactions, Relationships, Vocabulary, Phrases) and only four
     vocabulary rows shipped.

Fixes, all local to SlangReferenceDialog and _open_slang_reference:

  * After construction, lift, focus, and copy the parent's topmost
    flag. Reuse path does the same.
  * Build the term list on after_idle, not inside __init__.
  * Catalogue row weight 3, draft weight 1. Label the list
    "Catalogue" so an empty frame is an obvious empty state.
  * If matches is non-empty and the scrollable frame still has no
    children after idle, schedule one retry.
  * One-line caption under the main-window button: "Local slang
    reference — not the Settings glossary." Optional Settings line
    pointing at that button. Do not merge the two stores.

State/config: none. Performance: one extra after_idle; 18 (later ~40)
cards, already capped at SLANG_MAX_VISIBLE_RESULTS = 30.

            # row 2 and grid the heading at row=1 with the category menu
            # so the list is unambiguously labelled. See insertion map.
            self.after_idle(self._present)

        def _present(self):
            """Lift above a topmost parent and fill the list after layout."""
            try:
                if bool(self.master.config_data.get("always_on_top")):
                    self.attributes("-topmost", True)
                self.lift()
                self.focus_set()
            except tk.TclError:
                return
            self._refresh()
            self._update_metrics()
            if (
                search_slang(self.query.get(), self.category.get())
                and not self.entries.winfo_children()
            ):
                self.after(50, self._refresh)

# PlumeApp._open_slang_reference (line 4553):

        def _open_slang_reference(self):
            existing = self._slang_reference
            if existing is not None:
                try:
                    if existing.winfo_exists():
                        if bool(self.config_data.get("always_on_top")):
                            existing.attributes("-topmost", True)
                        existing.lift()
                        existing.focus_set()
                        return
                except tk.TclError:
                    pass
            self._slang_reference = SlangReferenceDialog(self)

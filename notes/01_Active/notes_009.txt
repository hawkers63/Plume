1. Feature -- Await reply
------------------------------------------------------------------------
Name: one-click end of your turn

Rationale, grounded in the current code:

  A live exchange is now four separate clicks: Translate, Copy main
  translation, Swap, Clear. Swap (v1.4), Copy (with finishing touch),
  and Clear already exist as independent actions. None of them is the
  conversation loop itself.

  After you send a French message you almost always want the same three
  things at once: the composed text on the clipboard, the direction
  flipped to French -> English, and the left pane empty and focused so
  the incoming reply can be pasted. That is one intent, not three.

User-visible behaviour:

  1. A "Reply" button sits on the left-hand button row, between Clear
     and Translate.
  2. If a working main translation exists, it is copied exactly as
     "Copy main translation" already does (finishing touch included).
  3. Direction is inverted via the existing swap_direction() helper.
     Auto-detect is a no-op, as today.
  4. The input box is emptied and focused. The situation field is left
     alone (the scene rarely changes mid-thread).
  5. The right-hand result stays visible, so you can still see what you
     just sent until the next Translate replaces it.
  6. Disabled while a translation is in flight, matching Translate.

Files touched: C:\Plume\plume.py only (PlumeApp).

2. Feature -- Keep as-is
------------------------------------------------------------------------
Name: a short local list of names and terms the translator must not alter

Rationale, grounded in the current code:

  protect_text() already masks URLs, emails, @handles, #hashtags,
  ISO dates and a handful of other tokens, then restore_result_tokens()
  puts them back after the model returns. User-chosen names are the
  obvious gap: "Kes", "Hawkeye", a pet name, a brand. Today those go
  to the model unprotected and come back translated, gendered, or
  respelled.

  This is not a glossary of preferred translations and not a second
  prompt. It extends the existing placeholder pipeline with a short
  list of extra terms from config, applied longest-first so
  "Marie-Claire" wins over "Marie".

User-visible behaviour:

  1. Settings gains a "Keep as-is" box: one term per line, maximum 20
     terms, 40 characters each.
  2. Stored in plume_config.json as keep_as_is_terms (a JSON list).
     Local only; the live config is already gitignored.
  3. On Translate, each term is masked with the same PH-token scheme
     already used for URLs, then restored in the main translation and
     every alternative.
  4. Empty list: behaviour is identical to today.
  5. Matching is case-sensitive and bounded on both sides so "Ann"
     does not eat "Anne" or "annual".

4.6 Insertion -- helpers, section 3, immediately before protect_text

    def normalise_keep_as_is_terms(value) -> list:
        """Return a short, de-duplicated list of keep-as-is terms.

        Accepts a list or a comma/newline-separated string so a hand-edited
        config and the Settings box share one sanitiser. Empty entries,
        oversized entries and case-insensitive duplicates are dropped.
        """
        if isinstance(value, str):
            parts = []
            for line in value.replace(";", "\n").splitlines():
                parts.extend(line.split(","))
            value = parts
        if not isinstance(value, list):
            return []
        seen = set()
        out = []
        for item in value:
            term = str(item or "").strip()
            if not term or len(term) > KEEP_AS_IS_MAX_CHARS:
                continue
            key = term.casefold()
            if key in seen:
                continue
            seen.add(key)
            out.append(term)
            if len(out) >= KEEP_AS_IS_MAX_TERMS:
                break
        return out

    def keep_as_is_pattern(term: str):
        """Compile a case-sensitive, token-bounded pattern for *term*."""
        return re.compile(r"(?<!\w)" + re.escape(term) + r"(?!\w)")

4.7 Change -- protect_text signature

File   : plume.py
Function: protect_text  (section 3)

Current signature:

    def protect_text(text: str, enabled: bool = True):

Replace with:

    def protect_text(text: str, enabled: bool = True, extra_terms=None):
        """Replace protected material with ordered tokens.

        Returns (masked_text, mapping). *extra_terms* is an optional
        sequence of keep-as-is names, applied longest-first before the
        built-in placeholder patterns so a user term cannot be swallowed
        by a later URL or date match.
        """
        if not enabled or not text:
            return text, {}
        mapping = {}
        counter = [0]

        def _sub(match):
            token = PH_TOKEN.format(counter[0])
            counter[0] += 1
            mapping[token] = match.group(0)
            return token

        masked = text
        terms = sorted(
            [t for t in (extra_terms or []) if t],
            key=len,
            reverse=True,
        )
        for term in terms:
            masked = keep_as_is_pattern(term).sub(_sub, masked)
        for pattern in _PROTECT_PATTERNS:
            masked = pattern.sub(_sub, masked)
        return masked, mapping

Existing callers that omit extra_terms keep today's behaviour.

    def test_keep_as_is_masks_and_restores_a_name():
        masked, mapping = protect_text(
            "Tell Kes I am on my way.", extra_terms=["Kes"]
        )
        assert "Kes" not in masked
        assert restore_tokens(masked, mapping) == "Tell Kes I am on my way."

    def test_keep_as_is_longest_term_wins():
        masked, mapping = protect_text(
            "Marie-Claire called.", extra_terms=["Marie", "Marie-Claire"]
        )
        restored = restore_tokens(masked, mapping)
        assert restored == "Marie-Claire called."
        assert len(mapping) == 1

    def test_keep_as_is_does_not_eat_longer_word():
        masked, mapping = protect_text(
            "Anne is arriving.", extra_terms=["Ann"]
        )
        assert masked == "Anne is arriving."
        assert mapping == {}

    def test_normalise_keep_as_is_terms_caps_and_dedupes():
        got = normalise_keep_as_is_terms(["Kes", "kes", "  ", "A"*41, "Hawkeye"])
        assert got == ["Kes", "Hawkeye"]

    best" rather than trying to detect that automatically.
  - Case-sensitive by design: the restored token is the original
    substring, so "Kes" stays "Kes" even if the model wanted "kes".

3. Feature -- Always on top
------------------------------------------------------------------------
Name: keep Plume above the chat window it is translating for

Rationale, grounded in the current use:

  Plume is a conversation helper. The other half of the conversation
  lives in a browser or a messenger. Today the translator disappears
  the moment that window is focused, so the user is constantly
  alt-tabbing. A single topmost flag is the whole feature: no overlay
  mode, no compact layout, no tray icon.

User-visible behaviour:

  1. Settings gains a checkbox, "Keep Plume on top of other windows",
     off by default.
  2. Ticking it and saving calls the existing Tk topmost attribute.
  3. The flag is persisted in config as always_on_top (bool) and
     applied on the next launch.

            """Honour the Settings flag. Safe to call before or after mapping."""

  - Do not also set -toolwindow or withdraw-to-tray. That would be a
    different, heavier feature.

4. Deliberately not proposed
------------------------------------------------------------------------
  - Casual slang finishing-touch group (tkt, grave, ...). ROADMAP.md
    already flags this as a later phase after the emote group has been
    lived with. Not due yet.
  - Number-key copy of alternatives (Ctrl+1..5). Useful, but the cards
    already have Use this / Copy / Speak; shortcuts can wait until the
    Reply loop is in.
  - A second "conversation memory" prompt. Situation already carries
    free-form context; stuffing the previous turn into the envelope
    would compete with it and risks instruction bleed.
  - Compact / overlay / system-tray mode. Always-on-top is the 90
    percent solution without a second layout.
  - Exporting favourites to a study file. Fine later; not the live loop.

------------------------------------------------------------------------
5. Suggested sequence
------------------------------------------------------------------------
  A. Always on top  -- smallest, Settings-only, no translation path.
  B. Await reply    -- one button, reuses Swap + Copy main.
  C. Keep as-is     -- touches protect_text / translate / Settings;
                       needs the four tests above.

Each is independently shippable. A then B is a usable v1.9 even if C
slips.

1. EXECUTIVE SUMMARY

A. Add an About panel directly beneath the Settings heading. Show the
application name, current version, purpose and existing copyright notice:
Copyright (c) 2026 Mark Hawksworth. All rights reserved.
This makes ownership discoverable inside the application and avoids another
toolbar control or another window to manage.

B. Add a "Lowercase translations" checkbox beneath the output alternatives.
It converts the displayed and copied translation text locally, including
finishing touches. Unticking it immediately restores the original casing.
Example: "Je viens d'Auridia ! xD" becomes "je viens d'auridia ! xd".
There is no additional translation request or API cost.

Recommend two separately reviewable releases: About first, lowercase second.
Version numbers remain unassigned until implementation is authorised.

The standing mandate's five priority areas are considered below against the
current code. They are context, not five additional unimplemented features.
The two additions above are the scope of this note.

2.B Lowercase translations: behavioural contract

Apply Unicode str.lower() only at the presentation/clipboard boundary.
Keep _current_main and _current_result in their original form. Never
lowercase the input, prompt, response JSON, glossary or history storage.
Do not use casefold(): it is intended for caseless matching and can change
text more aggressively, such as converting German ß to ss. Python's lower()
retains accents, but Unicode casing can change code-point count, so recalculate
metrics from the displayed string. Reference:
https://docs.python.org/3/library/stdtypes.html#str.lower
https://docs.python.org/3/library/stdtypes.html#str.casefold

Scope matrix:

Surface                              Proposed behaviour when checked
Main translation display             Lowercase, including appended touches
Alternative translation labels       Lowercase; meaning checks unchanged
Copy main / Reply                    Lowercase composed translation
Individual alternative Copy          Lowercase composed translation
Copy five / Copy five as HTML        Lowercase translations; existing numbering
Copy main as HTML                    Same translation as plain Copy main
Copy all                             Lowercase main and alternative translations;
                                     source, situation, headings and meanings
                                     retain their existing casing
Copy source / phrasebook Copy         Existing original text
History Copy / History export        Existing stored original text
Markdown study sheet / diff export   Existing original-cased study material
Speak / Use as input / Add glossary  Existing original translation

This is a chat-output preference, not a document-wide case converter.
Use as input keeps its existing raw-text semantics; pasting copied lowercase
text remains available when that is deliberately wanted as the next source.
Reply's clipboard honours lowercase, while its previous-exchange context
keeps the original accepted translation. Favourite and Undo Clear preserve
their raw snapshots; reopening either result applies the current display mode.

Strict lowercase also lowercases proper names, acronyms, Latin-letter emotes,
Keep-as-is terms and case-sensitive strings within translated output. Thus
Auridia becomes auridia and xD becomes xd. Keep-as-is still protects wording
from translation, but this explicit local formatting mode overrides casing
on display/copy. Show the following help text in the output footer:
"Display and chat copies only. Names and exact tokens also become lowercase."
This is material to the proposed feature, especially for URLs, placeholders
and commands. Users needing exact casing should leave the option unticked.
Do not silently introduce exceptions while calling the mode all-lowercase.

Ordering: raw translation -> existing finishing-touch composition where
applicable -> lowercase -> existing optional French typography for clipboard
operations -> HTML escaping/CF_HTML construction. Never lowercase completed
HTML markup. Copy five continues to omit touches. Copy all continues to add
touches to the main translation only. French typography remains copy-only.

State and persistence: first release uses one ctk.BooleanVar, initially False,
for the current application session. Clear, Undo Clear, Reply and new results
retain the selection; restarting Plume resets it. No change to DEFAULT_CONFIG,
plume_config.json, the example configuration or history schemas. This is an
explicit scope choice; cross-session persistence was not requested.

If a remembered preference is subsequently desired, add lowercase_output:
false to DEFAULT_CONFIG and the example configuration; accept only a JSON
boolean at load time (the string "false" must not turn it on). Use the existing
atomic save_config path, preserve damaged-file protection, and reconcile
SettingsDialog's open-time snapshot with the live output preference before
saving. That extension needs its own save/failure tests; it is not secretly
included in these session-only snippets.

Visual specification: pin an output footer at right-pane grid row 6 beneath
the row-5 alternatives; move the existing advisory to row 7. Keep row 5 as
the sole vertically expanding output row. Use horizontal padding 12 and
bottom padding 8; checkbox height 24, box 20x20, width 220, Segoe UI 13;
fill #1F6AA5, hover #144870, text #F2F2F2. Place the help text on a separate
wrapping line, Segoe UI 12, #C7C7C7. Budget roughly 60-80 logical pixels,
depending on wrapping. Do not assume the current alternatives viewport has
spare height at 1000x600; verify it with a visible advisory and long results.

Performance/lifecycle: six bounded strings are reformatted on a toggle.
Update existing labels rather than rebuilding the result or cards. Calling
_render_result on a toggle would reset a promoted "Use this" main translation,
stop speech and alter favourite state. No widget work belongs on a worker
thread here; the callback performs only in-memory formatting on the UI thread.
An in-flight translation continues normally and renders with the current
checkbox value when its accepted result arrives.

3.C Pure formatter — insert before adopt_main_translation

```python
def format_translation_case(text: str, lowercase: bool = False) -> str:
    """Format output casing without changing the stored translation."""
    return text.lower() if lowercase else text
```

3.E PlumeApp methods — insert beside _refresh_primary_display

```python
def _display_translation(self, text):
    """Apply the live output preference to a raw translation."""
    return format_translation_case(text, self.lowercase_var.get())


def _on_lowercase_change(self):
    """Refresh text without resetting the accepted result or selection."""
    self._refresh_primary_display()
    variations = (self._current_result or {}).get("variations", [])
    for index, (card, variation) in enumerate(
        zip(self._variation_cards, variations), start=1
    ):
        card._translation_label.configure(
            text="{}. {}".format(
                index, self._display_translation(variation["translation"])
            )
        )
```
